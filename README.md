# Blowdown

A demolition puzzle game for phones and browsers. Rig a building with charges, set
when each one fires, and bring it down inside the target zone without touching anything
next to it. Hit a neighbour and the job fails on the spot.

**Play:** https://zin34.github.io/Blow-Down/

Built with plain JavaScript, [Three.js](https://threejs.org) for graphics, and
[Rapier](https://rapier.rs) for physics. The game needs no build step.

## What's in it

- **30 jobs in three chapters**, from an old shed to a pair of linked skyscrapers. Each job
  has three stars (bring it down safely, land it in the zone, stay under budget) plus an
  Expert goal.
- **Daily contract:** a new building every day, the same for everyone, generated from the
  date. Before you see it, a headless solver checks it can be won and sets its par. It comes
  with a shareable result card and a streak.
- **Remixes:** up to three twists per finished job (Tight budget, Close quarters at night,
  Pinpoint zone), each verified solvable.
- **Progression:** cash for new stars, company ranks from Rookie to Tycoon, and a shop.
  The shop sells cutter and heavy charges, a long fuse, explosion colours, detonator skins
  and crew mascots.
- **Sandbox:** charges on anything holding up any building you've reached.
- **Clips:** save the slow-motion replay as a video, or share it straight from a phone.
- **Sparky:** the foreman gives hints, and will rig the solution for you for $300.

## Run it locally

```
node serve.js
```

- On this computer, open http://localhost:5190
- On a phone on the same Wi-Fi, open the "phone" address the server prints.
  If the phone can't connect, allow Node through Windows Firewall for private networks.

On a wide screen the game shows in a phone-shaped frame so the layout matches a phone.

## Controls

| Action | Mouse and keyboard | Touch |
|---|---|---|
| Place or remove a charge | Click a glowing spot | Tap a glowing spot |
| Rotate camera | Drag, right-drag, or A / D | Drag one finger |
| Zoom | Wheel, or W / S | Pinch |
| Move camera | Middle-drag or Shift-drag | Two-finger drag |
| Set when a charge fires | Drag its dot on the timeline, or scroll over it | Drag its dot |
| Select a charge / change its delay / remove it | Tab / ← → / Delete | Tap its dot |
| Charge type (once bought) | 1 / 2 / 3 | Buttons above the timeline |
| Detonate | Space or Enter | DETONATE button |
| Replay, retry, pause | V, R, Esc | Buttons |

Testing keys: **F1** stats overlay, **[ ]** previous/next job, **T** slow motion.

## How the physics works

`src/structure.js` holds the core logic. Buildings are made of chunks (columns, slabs, walls,
facade panels) held together in rigid groups. When charges destroy chunks, whatever sits above
each blasted height is checked:

- **Not enough support left** (below `minSupport`, default 40% of the original area): the
  rest buckles and drops straight down.
- **Enough support, but the centre of mass is outside what's left:** the remaining supports
  act as a hinge and it tips toward the cut.
- A falling block that hits hard or comes to rest breaks into single pieces. Most columns
  turn to dust, and pieces crumble inward, so well-rigged buildings pancake.

Results are deterministic, so the same rig always gives the same collapse.

## Tuning levels

From the browser console:

```js
const t = await import('./src/devtests.js');
await t.run()          // every job's good and bad rig; each line should say OK
await t.run(4)         // one job, or t.run([20, 29]) for a range
await t.bake()         // re-derive Expert goals and remix pars; paste the output into baked.js
```

The collapses are chaotic, so a small change in one place can move a result somewhere else.
Re-run the checks after changing physics constants or a level.
